# 🔐 Защита блога: как я добавил авторизацию и понял, что такое сессии, декораторы и секреты

До этого этапа мой блог был полностью открыт. Любой, кто знал ссылку `/create`, мог добавить пост, изменить контент или просто проверить форму. Для обучения — удобно. Для реального проекта — неприемлемо.

На этом шаге я добавил систему входа, защитил админку и, что важнее, **понял, как веб-приложения "помнят" пользователя между запросами без базы данных**. Ниже — без воды, только практика, код и инсайты.

---

## 🌐 1. Сессии: как приложение узнаёт вас
HTTP — протокол без памяти. Каждый запрос к серверу независим. Чтобы "запомнить", что вы вошли, используют **сессии**.

В Flask это объект `session`, который работает поверх зашифрованных cookie:
```python
from flask import session

# При успешном входе
session["logged_in"] = True
# При выходе
session.pop("logged_in", None)
```
---
## 🛡️ 2. Декораторы: защита маршрутов без дублирования кода
Раньше я бы писал проверку `if not session.get("logged_in")` в каждой функции. Это ломает принцип DRY. Написал кастомный декоратор:

```python
from functools import wraps
from flask import redirect, url_for, request

def login_required(f):
    @wraps(f)
    def decorated_function(*args, **kwargs):
        if not session.get("logged_in"):
            return redirect(url_for("login", next=request.url))
        return f(*args, **kwargs)
    return decorated_function
```
---
##💡 Что понял:
**Декоратор** — это просто функция, которая принимает функцию и возвращает обёртку.
`@wraps(f)` сохраняет имя, докстринг и метаданные исходной функции (критично для отладки и роутинга).
Паттерн `next=request.url` → после входа пользователь возвращается туда, куда пытался зайти изначально. Это стандартный UX-паттерн.

##🔑 3. Секреты и переменные окружения
Хардкодить пароли и ключи в коде — путь к утечкам. Перешёл на чтение из окружения:
```python
import os
app.secret_key = os.environ.get("SECRET_KEY", "пароль")
ADMIN_PASSWORD = os.environ.get("ADMIN_PASS", "пароль")
```
---
##💡 Что понял:
`os.environ.get()` позволяет задавать безопасные фоллбэки для локальной разработки.
В продакшене секреты выносятся в `.env` или настройки хостинга.
Правило: ничего секретного не попадает в коммиты.

##🎨 4. Условный рендеринг в Jinja2
Интерфейс должен реагировать на статус пользователя. В шаблоне `base.html` это выглядит так:

```python
{% if session.logged_in %}
    <a href="/create" class="btn btn-outline-light btn-sm">➕ Новый пост</a>
    <a href="/logout" class="btn btn-outline-danger btn-sm">🚪 Выйти</a>
{% else %}
    <a href="/login" class="btn btn-outline-light btn-sm">🔐 Войти</a>
{% endif %}
```
---
##💡 Что понял:
`session` автоматически доступен во всех шаблонах `(Flask injects it)`.
Условный рендеринг ≠ логика в представлении. Это презентация состояния, а не бизнес-правила.

---
##🔒 **Главный инсайт:** Безопасность — это не фича, а процесс. Даже простой блог учит мыслить как инженер: что если ключ утечёт? что если сессию перехватят? как откатить доступ?
##💬 А как вы защищаете учебные проекты?
Используете сессии или JWT?
Храните секреты в `.env` или в менеджерах паролей?
Ставили ли уже `werkzeug.security` для хеширования?
Делитесь в комментариях. Даже маленькие проекты учат большим принципам. 🐍🔐
